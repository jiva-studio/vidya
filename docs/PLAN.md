# План: объединение Classroom и Vidya

Статус: черновик, согласован в обсуждении 18.09.2026. Один вопрос открыт — см. конец.

## Зачем этот документ

Vidya и Classroom — один продукт, разошедшийся на две кодовые базы. Classroom
писался раньше и имеет работающие админку и мобильное приложение, но без
мультиарендности. Vidya — переписанный бэкенд со школами и правами, но без
единой строчки фронтенда. Задача: собрать одно целое.

Конечная цель: админка, где заводят школу, назначают людей с правами, создают
курсы; мобильное приложение, которое выкачивает курс и работает офлайн —
студент проходит уроки и сдаёт домашки, преподаватель их проверяет.

| `archive/classroom-backend` | 74 файла | контроллеры курсов, уроков, групп, записей | образец, переписываем |

Архив не трогаем — это единственная копия истории.

## Принятые решения

### Синхронизация — из Lectorium, не managed

Рассматривались PowerSync и ElectricSQL. Отвергнуты: они реплицируют саму базу
Postgres на клиент, то есть встают вместо API. Задача другая — админка пишет
через REST, мобилка через REST выкачивает. Репликации БД здесь нет.

Готовой библиотеки под стек не существует. В Lectorium движок не пакет:

- порты и типы HLC — `libs/domain/ports/*`, `libs/domain/sync/types.ts`
- SQL-адаптеры, outbox, journal-декоратор — `apps/mobile/infra/repositories/sql/`
- сценарии `pullAndMerge` / `pushLocal` — `apps/mobile/usecases/sync/`

Клиентская часть ~2670 строк TypeScript — переносится копированием. Серверная
половина в Lectorium написана на Go (`services/profile`), поэтому у нас это два
эндпоинта на NestJS: `pull` с курсором и `push` с HLC.

Ключевое свойство, ради которого всё это берётся: каждое изменение пишется в
`outbox` **в той же транзакции**, что и доменная запись, со штампом Hybrid
Logical Clock. В Classroom синхронизация была наивной — `download*` перезаписывал
всё целиком, без курсора, без аплоада конфликтов, без атомарности.

### SQLite только на мобилке

Веб — и админка, и любой будущий кабинет — ходит в REST. Локальной базы там нет,
поэтому спор `sql.js` против OPFS не возникает вовсе. На устройстве
`@capacitor-community/sqlite` за портом `ports/app/persistence.ts`.

### UI — две библиотеки

- `libs/ui` — shadcn-vue + Tailwind 4, только веб
- мобилка — Ionic + `kit/ui`

Шарятся не компоненты, а слои под ними: `libs/domain`, `libs/protocol`,
`libs/usecases`.

Рассматривался PrimeVue: у него сильнее таблицы, но тяжёлых гридов в этом
проекте нет, а его unstyled-режим чинит внешний вид и не чинит поведение
компонента. Старые `CrudForm`/`CrudTable` из classroom-admin не переносим —
собираем заново на shadcn-vue.

### Один сервис, одна база

Микросервисов нет. `sync` и `media` — модули внутри `services/api`.
`services/database` растворяется: `.sql` переезжают в API, сущности остаются
в `libs/entities`.

### Контент — документ, результаты — строки

Уроки, секции и блоки хранятся **JSON-ом** в `lessons.content`. Причина: блоки
полиморфны (`video` / `audio` / `text` / `quiz` имеют разные поля), а
полиморфизм в SQL требует либо широкой таблицы с `NULL`, либо EAV, либо таблицы
на тип — и в любом случае JSON-колонки для `answers[]` и `timestamps[]`. Плюс
редактор: сохранение урока остаётся одним `UPDATE`, а не транзакционной
пересортировкой строк.

Условия, без которых это не работает:

- секции и блоки несут **устойчивые UUID**, выданные в редакторе при создании
- идентификаторы никогда не переиспользуются
- индекс массива идентификатором быть не может

Целостность закрывается не внешним ключом, а **снимком**: домашка хранит копию
секции, на которую отвечали. Это нужно независимо от способа хранения — контент
меняется, и без снимка проверяющий увидит не то задание, которое решал студент.
Удаление секции со сданными работами запрещаем на уровне API.

Прогресс, ответы, домашки и оценки — обычные таблицы с обычными индексами.
Аналитика считается по ним, а не по контенту.

### Медиа — по источнику

Блок несёт дискриминатор:

    { "type": "video", "source": "upload",  "url": "…" }   → можно скачать
    { "type": "video", "source": "youtube", "id":  "…" }   → только встроить

Клиент смотрит на `source`: `upload` кладётся в офлайн-очередь, остальное
показывается плеером при сети.

### Локализация

Fluent (`.ftl`), локали en и ru уже написаны в classroom. Оставляем.

## Модель доступа

Две независимые оси, смешивать нельзя:

- **Сотрудник школы** — `PermissionKey` со скоупом по `schoolId`. Уже работает.
- **Студент** — аккаунт плюс записи на курсы. Прав в этом смысле нет, доступ
  даёт `enrollment`. Записей у одного студента несколько.

Каталог курсов виден студенту без записи.

Преподаватели работают и в мобильном приложении: получают сданные работы своих
групп и ставят оценки. Значит, у каждой коллекции в outbox своя видимость,
зависящая от роли, — синхронизация не только для студентов.

### Запись на курс

С модерацией. Запись идёт **на курс**, `groupId` остаётся пустым; группа
назначается потом отдельным действием. Студент может записаться, когда групп
ещё нет, и ждать в очереди, пока подходящая не появится.

В схеме это уже заложено: `enrollment.groupId` nullable, `groups.courseId NOT NULL`.

### Домашки

Цикл: `open → pending → in-review → returned → accepted`. На `accepted`
выставляется оценка. Квизы проверяются автоматически, остальное — преподавателем
с возможностью вернуть на доработку.

Бэкенда под домашки не существует нигде: в Classroom они жили только как агрегат
на мобилке. Проектируются с нуля.

## Синхронизация: что и куда

| Данные | Направление |
|---|---|
| курсы, уроки, секции, блоки | только вниз |
| прогресс по блокам | вверх |
| ответы на домашки | вверх |
| статус проверки и оценка | вниз |
| запись на курс | вверх (подача), вниз (решение) |
| сданные работы для преподавателя | вниз |
| оценки от преподавателя | вверх |

## Целевая структура

    modules/
    ├── libs/
    │   ├── domain/        сущности, инварианты, порты. Ноль зависимостей
    │   ├── protocol/      контракты по проводу, включая модель уроков
    │   ├── persistence/   типы строк клиентской БД
    │   ├── usecases/      сценарии, общие для веба и мобилки
    │   └── ui/            shadcn-vue + Tailwind 4 — только веб
    ├── apps/
    │   ├── admin/         Vue 3 + Vite
    │   └── mobile/        Ionic 8 + Capacitor 8 + kit
    ├── plugins/           нативные Capacitor-плагины
    └── services/
        └── api/           NestJS: edu, auth, sync, media — модулями

Мобильное приложение раскладывается гексагонально, как в Lectorium:
`ports/` (интерфейсы) → `infra/` (адаптеры) → `usecases/` (сценарии) → `ui/`.
Адаптеры не импортируют друг друга — только порты и домен.

## Миграции

Две независимые системы. Общего между ними нет ничего, кроме имён сущностей.

| | Сервер | Устройство |
|---|---|---|
| Что | `.sql`-файлы, руками | TS-миграции, руками |
| Кто катит | API при старте, до `listen()` | приложение при старте |
| Учёт | `schema_migrations` | `migrations` (`kit/persistence`) |
| Направление | только вперёд | только вперёд |

Генераторы схемы из ORM (Atlas, `typeorm migration:generate`) отвергнуты: в
миграциях сюрпризы дороже всего, SQL пишем сами.

Восемь существующих миграций переносятся в `.sql` механически — SQL уже написан
руками внутри `queryRunner.query()`.

### Требования к раннеру

1. Отдельное соединение, **не из пула**: advisory lock у Postgres сессионный.
2. Каждый файл в своей транзакции.
3. Пустая папка миграций — ошибка, а не успех. Иначе `.sql` не попадут в образ,
   раннер отчитается об успехе, и приложение упадёт на первом запросе.
4. Файлы копируются в Docker-образ явно, путь берётся из `VIDYA_MIGRATIONS_DIR`.

Откат делается новой миграцией: откатив образ, схему не откатишь. `down` не пишем.

Сиды (`@vidya/seeder`) при старте **не** запускаются — только `make seed`.

### Попутно

`services/database/main.ts` захардкожен на `localhost` / `postgres` / `postgres`.
Исчезает вместе с переносом миграций в API, где конфиг уже берётся из окружения
(`VIDYA_DB_*`).

`synchronize` у TypeORM нигде не включён — проверено.

## Этапы

**1. Фундамент.** Модель уроков (секции → блоки) в `libs/protocol`. Ключи прав
`courses` / `lessons` / `groups`. Сущности и таблицы `enrollments`, `homework`,
`progress`. Перенос восьми миграций в `.sql` плюс раннер в API.
Версии: NestJS 11, Node 22, Vue 3.5, Tailwind 4, Ionic 8, Capacitor 8.

**2. API обучения.** `edu/courses`, `edu/lessons`, `edu/groups`,
`edu/enrollments`, `edu/homework` — по образцу classroom-backend, но со скоупами
и тестами в стиле существующих 78. Снимает блокировку со всего остального.

**3. Синхронизация.** Перенос outbox, HLC и курсоров из Lectorium. На сервере —
`pull` и `push` с серверной валидацией. Порт `ports/app/persistence.ts` и адаптер
под Capacitor.

**4. `libs/ui`.** shadcn-vue + Tailwind 4 с нуля. Из classroom-admin берём только
раскладку экранов и локали.

**5. Админка.** OTP, школы, роли, пользователи, курсы, группы, модерация записей,
проверка домашек.

**6. Мобилка.** Перенос агрегатов и сценариев, PouchDB выбрасывается, SQLite через
`kit`. Офлайн-чтение курса и запись домашек в outbox.

**7. Медиа.** В Classroom `media`-контроллер был заглушкой: `console.log`, файл
никуда не сохранялся. Нужны хранилище и подписанные ссылки.

Порядок: 1 → 2 строго последовательно. Дальше 3 и 4 параллельно, затем 5 и 6.

Студенческий веб-кабинет отложен. В структуре место под него не резервируем.
