## Что берём из архива

Архив склонирован в `resources/archive` (sparse: `classroom-admin`,
`classroom-backend`). Это единственная копия истории — только читаем.

`classroom-admin` — 4569 строк, Vue 3 + Tailwind + headlessui + heroicons +
Fluent. Разбор по частям:

| Часть архива | Решение |
|---|---|
| Раскладка экранов: list-страница → crud-страница, `routes.ts` на домен, breadcrumbs в `meta` | **берём как схему** |
| Сайдбар: группы `org` / `edu` / `fin`, пункты с иконками и вариантом активности | берём структуру, пункты приводим к нашим правам |
| Локали `.ftl` (en/ru) по доменам: `courses`, `groups`, `enrollments`, `roles`, `users`, `permissions`, `sidebar`, `breadcrumbs`, `actions` | **берём тексты**, ключи переименовываем под новые сущности |
| `shared/components/Crud/*` (`CrudForm`, `CrudTable`, 8 полей ввода) | **не переносим** — собираем заново на shadcn-vue (решение из PLAN.md) |
| `shared/components/Kit/*` (Table, Button, Input, Avatar, Breadcrumbs) | не переносим — это и есть shadcn-vue |
| `shared/services/Service.ts` — свой fetch с ретраями и интерцепторами | не переносим: у нас уже есть `HttpClient` + `FetchHttpClient` в мобилке |
| `auth/composables/useWithAuthentication.ts` — мутирует сервис, пушит интерцепторы при каждом вызове | не переносим; поведение «401 → refresh → повтор» переносим как идею |
| `shared/models/Permissions.ts` — свой список прав (`org-roles-manage`, …) | выбрасываем: права теперь `PermissionKeys` из `@vidya/domain` |
| Редактор уроков | в архиве **отсутствует** — писать с нуля |

Три бага архива, которые не тащим: `i18n.ts` грузит en-ресурсы в `ruBundle`;
интерцептор `onError` бьёт в refresh на любой статус, не только 401;
`useWithAuthentication` добавляет интерцепторы повторно на каждый вызов.

## Как переиспользуем компоненты

Вопрос «взять старое и переделать или написать новое» решается по слоям, а не
целиком.

**Берём из архива как есть — поведение и тексты, не код:**

- какие экраны существуют и как связаны (список → форма, `:id = new` для
  создания, breadcrumbs в `meta` роута);
- какие поля в каждой форме и какие колонки в каждой таблице;
- раскладка сайдбара по разделам;
- локали `.ftl` — переносятся файлами, правятся только ключи.

**Пишем заново — сам компонент.** `CrudForm`, `CrudTable` и `Kit/*` из архива —
это самодельная мини-библиотека: свои `Table`, `Input`, `Button`, свой
комбобокс, свой пикер даты. Переделывать её дороже, чем собрать то же самое на
готовом, — и решение уже записано в `PLAN.md`.

Но «заново» не значит «с нуля руками»: компоненты shadcn-vue добавляются его
CLI из upstream в `libs/ui` и дальше правятся под нас. То есть кнопку, инпут,
таблицу и диалог мы не изобретаем — мы их получаем, а пишем только то, чего в
shadcn-vue нет: форма со списком полей, панель действий, состояния загрузки,
пустоты и ошибки.

**Не переносим вообще:**

- `Service.ts` с самодельным fetch и ретраями — вместо него `HttpClient` из мобилки;
- `useWithAuthentication` — заменяется одной сборкой клиента в корне приложения;
- `Permissions.ts` со своим списком прав — права берутся из `@vidya/domain`;
- `useTheme` и `runConfigPersistence` — переключение оформления выброшено.

**Правило простоты.** Компонент содержит то, что показывает его экран. Никаких
вариантов «на будущее», никаких обёрток над обёртками, никакой логики
оформления. Тот же функционал и те же слои, что в архиве, — но без
переусложнения.

## Стек

- Vue 3.5, Vite, TypeScript, `vue-router` 4
- Tailwind 4 + shadcn-vue (`reka-ui` под ним) — в `libs/ui`
- Fluent (`@fluent/bundle` + `fluent-vue`) — локали из архива
- `@vueuse/core` — `useAsyncState`, как в архиве
- Vitest + `@vue/test-utils`
- одна тема, без переключателей оформления
- состояние: composables + `provide/inject`, без Pinia, пока не понадобится

Правила из `.agents/rules/coding-style-frontend.md` действуют с первого коммита:
файл ≤ 350 строк, `<template>` ≤ 100 и глубина ≤ 4, `<script>` ≤ 300, типы в
соседнем `types.ts`, классы и `cva` в `styles.ts`, секции `Props / Events /
State / Hooks / Handlers / Helpers`.

## Мультиарендность

Школа — не параметр URL, а состояние сессии. Из `AccessToken.permissions`
(`UserPermission[]`: `sid` + `p`) строится список доступных школ; выбранная
лежит в composable `useCurrentSchool()` и подмешивается в запросы как
`schoolId` (`GetCoursesQuery`, `GetUsersQuery` его уже принимают).

Из того же списка прав рассчитывается видимость: пункт сайдбара и кнопка
действия показываются, если у текущей школы есть нужный `PermissionKey`.
Скрытая кнопка — удобство, отказ всё равно за сервером.

Смена школы сбрасывает списки и возвращает на индекс раздела.

## Экраны

Каждый раздел — пара «список → форма», как в архиве.

**org**
- Школы: список, создание, редактирование, настройки (`schools/:id/configs`)
- Роли: список, форма с чекбоксами по `PermissionKeys`, сгруппированными по префиксу
- Пользователи: список, форма, назначение ролей и школ (`users/:id/roles`, `users/:id/schools`)

**edu**
- Курсы: список, форма (`name`, `description`, `learningType`)
- Уроки курса: список с номерами и версиями; кнопка «Редактировать» ведёт в редактор
- Группы: список, форма, состав
- Записи: список с фильтром по статусу и курсу; действия «принять / отклонить» (`moderation`) и «назначить группу» (`group`)
- Домашки: очередь проверки с фильтром по статусу и группе; экран проверки — текст студента, оценка, «принять» или «вернуть» (`homework/:id/review`)

Экран проверки домашки обязан показывать `answeredSupersededVersion`: работа
сдана по версии, которая уже не опубликована. Рядом — ссылка на ту версию
урока, по которой отвечали.

**auth**
- Вход по OTP: почта → код → токены; refresh молча, выход чистит сессию

## Редактор уроков (4a)

Работает над `LessonContent` из `@vidya/domain`: `schemaVersion` + `sections[]`,
секция несёт `id`, `title`, `blocks[]` и `assessment` (`none | auto | teacher`),
блок — один из `text | video | audio | quiz`.

- Слева дерево секций, справа холст блоков. Порядок — drag-and-drop, при
  сомнении первым шагом кнопки «вверх / вниз», dnd потом.
- Блоки: `text` (textarea, без Markdown — решение из PLAN.md), `video` и `audio`
  (`source` из `BlockSources` + `url`), `quiz` (вопрос, варианты, правильный).
- **Идентификаторы выдаёт редактор в момент создания** — `crypto.randomUUID()`,
  и никогда не переиспользует. Индекс массива идентификатором быть не может: на
  секцию ссылаются сданные домашки.
- Предпросмотр — свои компоненты рендера, не общие с мобилкой: там Ionic, здесь
  shadcn-vue. Общий у них только тип `LessonContent`.
- Черновик сохраняется целиком: `PATCH lessons/:id/versions/:vid` принимает
  `{ content }`. Публикация — отдельная кнопка и отдельное право
  `lessons:publish`. Опубликованная версия заморожена: форма уходит в
  read-only, правки создают новую версию (`POST versions`).
- Удаление секции со сданными работами API запрещает — ошибку показываем
  текстом, а не «что-то пошло не так».

Это работа размером с остальную админку. Отдельная оценка, отдельные тесты.

## Порядок работ

1. **Каркас.** `apps/admin`: Vite, Tailwind 4, роутер, layout с сайдбаром,
   Fluent с локалями из архива (обе, и en в `enBundle`). Пустые страницы.
2. **Транспорт и сессия.** `ports/http.ts` + `FetchHttpClient` (форма — из
   мобилки), refresh на 401 с одной попыткой, `useSession`, `useCurrentSchool`,
   гварды роутера.
3. **`libs/ui`, первый срез.** Ровно то, что нужен шаг 4: Button, Input,
   Textarea, Select, Table, Dialog, Badge, форма с валидацией.
4. **org.** Школы, роли, пользователи — на них обкатываются табличный и
   формовый паттерны.
5. **edu, CRUD.** Курсы, уроки (список и метаданные), группы.
6. **edu, процессы.** Записи с модерацией, очередь домашек и проверка.
7. **Редактор (4a).** Секции, блоки, порядок, предпросмотр, черновик,
   публикация.
8. **Полировка.** Пустые состояния, ошибки, загрузки, права на кнопках, тёмная
   тема.

Шаги 1–2 последовательно, дальше 3 идёт вперемешку с 4–6 по потребности.
Редактор можно вести параллельно, начиная с шага 5.

## Критерий готовности

Админка закрывает свою половину критерия v1: школа заведена, курс создан, урок
написан и опубликован, студент принят и помещён в группу, сданная домашка
проверена и оценена. Всё — через интерфейс, без curl.

Каждый шаг заканчивается зелёным `make check` из корня.

## Решённые вопросы

- **`libs/usecases` не заводим.** Мобильные `usecases/education/*` — тонкие
  обёртки над GET, у админки почти всё на запись. Общего кода нет; сценарии
  живут в `apps/admin/src/<домен>/api/`.
- **Компоненты рендера блоков не шарим** с мобилкой: Ionic против shadcn-vue,
  общим остаётся только тип `LessonContent` из домена.
- **Загрузка файлов — заглушка** до этапа 7: поля принимают ссылку, область
  загрузки объясняет, что хранилища ещё нет, и в сеть не ходит.
- **Порядок — по разделам**, не вертикальным срезом.
- **Нет права — нет кнопки**: элемент не рендерится, серверная проверка остаётся.
- **Тесты**: один раннер Vitest; юниты на логику без DOM, монтажные тесты на
  интерфейс через поддельный `HttpClient`. e2e не заводим.

## Что делаем лучше, чем в архиве

- **Действия в списке, а не в карточке.** В архиве заявку принимают, открыв её
  страницу. Модерация — работа пачками: принять и отклонить прямо в строке,
  назначение группы диалогом.
- **Очередь домашек как рабочее место.** Для преподавателя это главный экран:
  список слева, ответ справа, оценка и возврат с клавиатуры, переход к
  следующей работе не через список.
- **Справочники грузятся один раз.** Записи и домашки ссылаются на курсы,
  группы и людей идентификаторами. Резолв — один запрос на страницу с кэшем, а
  не запрос на строку.
- **Три состояния у каждого экрана.** Загрузка, пусто, ошибка с повтором —
  в архиве нет ни одного из них, любая сетевая ошибка даёт пустой экран.
- **Поиск и фильтры над таблицей.** В архиве список отдаётся целиком и ничем не
  сужается; в записях и домашках это станет больно на первой же живой группе.
- **Хлебные крошки включены.** В архиве `TheBreadcrumbs` закомментирован в
  `App.vue`, хотя данные для него собираются в каждом роуте.
- **Ни одного поля, которое некуда сохранить.** Отдел, должность, статус
  пользователя, подзаголовок и обложка курса, дата старта и ведущий группы —
  в форму не попадают.
- **Главная показывает работу, а не ссылки.** Вместо доски быстрых действий —
  сколько заявок ждёт решения, сколько работ на проверке, у каких уроков висит
  неопубликованный черновик.

## Практики проектирования админок, которые применяем

Сверился с общепринятыми рекомендациями (NN/g, Smashing, разборы корпоративных
таблиц) и перевёл их в решения для нас, а не в общие слова.

**Форма: страница, панель или диалог.** Правило по объёму и по тому, нужен ли
контекст списка рядом.

| Приём | Где |
|---|---|
| Отдельная страница | длинные формы и всё, что имеет свой адрес: курс, урок, редактор, карточка пользователя |
| Боковая панель | правка одной записи, когда список нужен рядом: заявка, группа, домашка в очереди |
| Диалог | одно решение в один шаг: назначить группу, подтвердить публикацию, удалить |

Панель выигрывает у диалога там, где оператору нужно видеть фон: он сверяется
со списком и не теряет место. Диалог поверх таблицы этот контекст отрезает.

**Опасные действия: подтверждение или отмена.** Необратимое — подтверждаем
диалогом, который называет последствие («удалить секцию: ответы N студентов
перестанут открываться»), а не спрашивает «вы уверены?». Обратимое — делаем
сразу и показываем «Отменить» в тосте. Для нас это значит: удаление школы,
роли, курса, секции — диалог; отклонение заявки и возврат домашки — тост с
отменой, потому что их можно переиграть.

**Права: скрывать, а не гасить.** Отключённая кнопка уместна, когда действие
станет доступным (идёт загрузка, не заполнена форма). Недоступное по правам
скрывают — гашёная кнопка без объяснения только жжёт внимание. Это ровно то
решение, которое мы уже приняли (AC-7), теперь оно подпёрто практикой.

**Очередь на проверку — рабочее место, а не список.** Оператор обрабатывает
десятки работ подряд, поэтому: список слева, работа справа, `j` / `k` —
следующая и предыдущая, `a` — принять, `r` — вернуть, после решения фокус сам
уходит на следующую работу. Подтверждений на каждый шаг нет, вместо них отмена.
Тот же приём — в модерации заявок.

**Таблицы.** Фильтры над таблицей, а не в модалке; постраничность, а не
бесконечная лента — оператору нужно «вернуться на ту же страницу»; действия
строки видны при наведении и доступны с клавиатуры; у каждой таблицы три
состояния (загрузка, пусто, ошибка), и «пусто» объясняет, что сделать.

**Формы.** Сохранение явное, автосохранения нет — кроме редактора урока, где
черновик сохраняется по кнопке, а уход с несохранёнными правками перехватывается.
Валидация показывается при уходе с поля, а не на каждый символ; ошибка стоит у
поля, а сводка сверху — только если полей много.

**Блочный редактор.** Список блоков слева как оглавление и перетаскивание в нём
же, стрелки «вверх/вниз» как доступная альтернатива; у каждого блока меню с
дублированием и удалением; предпросмотр отдельной вкладкой, а не отдельной
страницей; состояния черновика и публикации подписаны прямо в шапке, история
версий доступна оттуда же.

**Мультиарендность.** Переключатель школ — в шапке сайдбара, рядом с именем
школы, а не в настройках. Школа живёт в сессии, не в адресе: адреса остаются
короткими, а смена школы сбрасывает загруженное, чтобы на экране не осталось
данных прошлой (AC-6).

## Локальный стенд

Порты по одной схеме, чтобы не держать в голове разнобой:

| | |
|---|---|
| `780x` инфраструктура | 7800 postgres · 7801 redis · 7802 smtp · 7803 почтовая морда |
| `781x` приложения | 7810 api · 7811 админка · 7812 storybook |

```bash
make dev-up                            # postgres, redis, mailpit в docker
make bootstrap EMAIL=you@example.com   # школа, роль владельца '*', пользователь
make dev                               # миграции, API и админка
make mail                              # ящик, куда падают письма с кодом OTP
make storybook                         # компоненты и экраны без API и базы
```

Код одноразового пароля нигде, кроме письма, не появляется — ни в логах, ни в
ответе API. Mailpit его перехватывает и наружу не шлёт, поэтому почтовые креды
локально не нужны. Файлы стенда уже лежат в ветке: `docker-compose.dev.yml` и
цели в `Makefile`.
